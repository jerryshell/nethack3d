# NetHack 3D

浏览器中的三维 NetHack 复刻，使用 Bun、TypeScript、Vite 与 three.js 构建。
怪物、物品与职业数据由脚本直接提取自 NetHack 5.0 的 C 源码，战斗判定沿用原版公式。

本页说明项目能力、操作方式与开发方式。架构细节见 `docs/DESIGN.md`，
已知边界与工程约定见 `docs/COGNITION.md`。

## 快速开始

```bash
bun install
bun run dev        # http://localhost:5273
bun run build      # 产物输出到 dist/
```

## 能力范围

### 忠于原版的数据与规则

- 394 个怪物，含等级、速度、护甲、魔抗、阵营、攻击骰与颜色。
- 441 件物品，覆盖 13 个类别，含伤害骰、护甲加值与材质。
- 13 个职业与 5 个种族，沿用原版的属性基准与生命、法力成长曲线。
- 命中与伤害公式移植自 `uhitm.c`、`mhitu.c`、`exper.c`：
  `find_roll_to_hit`、`AC_VALUE`、`abon`、`dbon`、`experience()`、`newuexp()`。
- 怪物生成使用原版难度窗口：下界为 `depth / 6`，上界为 `(depth + 玩家等级) / 2`。
- 物品生成权重取自 `mkobj.c`，未鉴定外观洗牌对应 `o_init.c` 的 `shuffle_all()`。

### 玩法

- 回合制移动，撞向怪物即攻击；怪物会在看见玩家后追击并推开门。
- 物品操作：拾取、持握、穿戴、脱下、喝、吃、读、挥杖、放下与金币拾取；充能卷轴可以给法杖补能。
- 远程：投掷物品自动瞄准视野内最近的怪物，持握弓弩射击投射类武器有命中加成，投出物可回收。
- 武器与法术技能：近战命中与成功施法都会积累对应熟练度，提供命中、伤害与失败率加值。
- 职业神器：每个职业在职业任务的最终层取得一件同名神器，仇敌守在神器旁，武器附魔计入命中与伤害，非武器神器提供被动抗性；背包里可以启动神器（揭示地图、层级传送、造箭、回法、治疗）。
- 容器：箱子与袋子可以放进与取出物品，踩在地面容器上可以搜划；诅咒容器打不开，口袋袋会放出怪物。
- 尸体：击杀按概率留下带怪物原型的尸体，吃掉获得营养；毒与酸尸体没有对应抗性时会受伤，
  尸体放久会腐坏致病；拥有抗性基因的怪物（如火焰巨人）按等级概率赋予内在抗性，无需装备；
  浮游眼等怪物的尸体会赋予隔墙感知怪物的心灵感应，会传送的尸体会赋予随机传送。
- 罐头：需要开罐器或手中武器才能打开，内容按层数抽取、偶尔变质，内容与状态随存档保留。
- 疾病：吃腐坏尸体会患病，患病期间停止自然回复并每五回合掉 1 点生命，
  状态栏会提示；祈祷与完全治疗药水可治。
- 小地图：右下角缩略图显示已探索地形、楼梯、设施与商店，玩家与视野内怪物也有标记，自动移动时显示路径。
- 状态标签：失明、混乱、隐形、沉睡、被缠、眩晕、石化等状态以「图标+文字」的彩色词条显示，计时状态标出剩余回合，危险状态用红色强调。
- 粒子：命中时喷出火花，击杀时爆散，火把旁升起飞灰；玩家与怪物在月光下投射实时阴影。粒子池容量固定，不产生运行时分配。
- 法术：46 种法术书按类别结算，代价等于法术等级，智力与职业决定成功率。
- 陷阱：踩中触发伤害、定身、睡眠、传送、掉层、腐蚀、变形与雕像活化等效果，触发前不可见。
- 地形设施：站在喷泉、水槽、坟墓或王座上会出现对应动作，效果随机（喝水、踹一脚、挖掘、坐下），效果表公开可见。
- 惩罚：读惩罚卷轴会招来锁在脚踝上的铁球，受罚期间隔一回合才能移动，铁球也丢不掉；向神祈祷可以解除。
- 挖掘：持镐向同一面墙连挖三回合、矮人锹两回合才能凿穿，中途挪开会重新计时；持镐站在地面还能向下挖穿地板、落到下一层；挖过的瓦片与挖掘进度随存档保留，推箱层禁止挖掘。
- 浮空：浮空药水、浮空戒指、浮空靴让人飘起来，可越过元素位面的虚空与岩浆、水流，也不会触发地面陷阱（魔法传送门除外）；浮空够不着楼梯，飞行护身符则不受此限。
- 深水：不会游泳又没有浮空时，站在水里每回合受伤；两栖形态、浮空与离水上岸都能免除溺水。
- 祈祷：按 `p` 向神祈祷，效果由站位、神坛归属、阵营记录与冷却决定；受罚会引来天使；
  把水放在祭坛上祈祷，水会随神意变成圣水或诅咒之水；祝福祈祷还能解除装备上的诅咒。
- 献祭：站在祭坛上献祭一具尸体，同阵营可提升幸运与阵营记录，异教祭坛有概率归附。
- 变形：喝变形药水、踩中变形陷阱或被怪物施加变形术会变成怪物形态，护甲、近战与抗性随形态改变，到期自动恢复。
- 宠物：开局按职业获得小猫、小狗或小马，会跟着你上下楼、主动打敌对怪物；撞到它会交换位置，喂食能让它成长，中大型宠物还能骑乘冲锋。
- 特殊楼层：第 5 层是无门的大房间，第 8 层的神谕所提供付费提示，第 20 层有美杜莎与雕像，第 25 层是大墓地（只有不死生物），第 27 层是要塞（士兵把守、有许愿魔杖），第 29 层是圣所（只有恶魔）。
- 分支地牢：第 4 层有通往矿坑的楼梯（8 层，侏儒与矮人，底层是带商店与喷泉的矿镇市集），第 14 层有通往职业任务的楼梯（5 层，主题随职业变化），第 16 层有通往巫妖塔的楼梯（4 层，不死生物，底层有首领与财富），第 18 层有通往卢迪奥斯要塞的楼梯（1 层，克罗伊斯与守军守着金币），第 8 层神谕所有通往推箱的楼梯（4 层，原版固定布局，从底层进入，可推巨石，顶层有次元袋或反射护身符）。
- 职业任务：首层是职业总部，领袖与护卫守在入口，交谈一次解锁下行楼梯，最终层的仇敌守在带门的巢穴里，神器也在室内；带神器回总部复命会得到嘉奖。
- 骨头文件：死亡后留下遗物，下一局在同一层会发现前任冒险者的遗物与幽灵。
- 怪物特殊攻击：火焰、寒冷、电击、酸液、毒素、睡眠、麻痹、吸能、吸级、
  偷窃、诅咒、去附魔、缠绕、分解与石化等按原型数据结算；
  戒指、护身符、龙鳞甲与反射盾提供对应抗性，近战命中还会触发被动攻击。
- 远程吐息：2–6 格外的怪物会用吐息、喷吐或魔法弹攻击，效果同样走抗性判定；醒来的怪物会唤醒附近同伴，重伤的怪物会逃跑。
- 商店：部分楼层有带店主的商店，分十种专营种类（杂货、武器、护甲、药水等），
  按各自库存表铺货；买入加三分之一、卖出半价，价格随魅力浮动，店主每 200 回合补货；
  店主在受挑衅前不会攻击。
- 鉴定系统：药水、卷轴、魔杖、戒指、护身符、法术书与宝石在鉴定前只显示随机外观，
  祝福状态在鉴定前不可见。
- 饥饿与饱食度阈值、失明、混乱、隐身的计时状态。
- 角色创建：职业、种族、阵营、性别可选，属性支持重掷并预览初始装备。
- 自动存档到 localStorage，标题页可继续游戏；死亡后清除存档。
- 通关目标：下潜 30 层取得尤恩多护身符，再带回第 1 层；尤恩多巫师会一路追杀。
  集齐开启之铃、祈祷烛台与死亡之书后，还可在圣所的振动方块上举行开启仪式，
  经传送门渡过土、气、火、水四层元素位面，到星界把护身符献给自己阵营的祭坛登神。

### 表现

- 地牢瓦片、墙体与液体使用 InstancedMesh，逐实例颜色表达三种迷雾状态：
  未见、记忆、可见。
- 门、楼梯、陷阱与人物使用 Kenney 素材（CC0），兽类与物品保留程序化几何体。
- 照明沿用原版的房间规则：玩家进入照明房间时整间可见。
- 相机随玩家平滑跟随，支持拖拽旋转与滚轮缩放。
- 怪物模型按字形类别区分昆虫、四足、人形、龙、软泥、灵体与蛇形。

### 国际化

- 英文与简体中文，运行时切换，无需刷新。
- 394 个怪物名、441 个物品名、13 个职业、5 个种族与 121 个外观词均有中文译名。
- 消息日志保存实体 ID 而非字符串，因此切换语言后历史消息也会重新翻译。

### 面向新手的界面

界面刻意减少了必须先记住的规则：

- 底部常驻当前目标，例如「下到第 2 层（共 30 层）— 找到向下的楼梯 ▼」。
- 情境操作栏只列出此刻可做的事：拾取、攻击、前往楼梯、等待、背包、帮助。
  「前往楼梯」在向下的楼梯已经探索过之后才会出现；按钮上标出对应快捷键。
- 光标悬停在格子上会说明「这是什么」与「点击会发生什么」，
  例如「向下的楼梯 ▼ / 点击：走过去即可下楼」。
- 背包里点击条目不再直接执行默认动作，而是展开动作菜单
  （持握、穿戴、喝、读、吃、挥动、放下），每项都标出快捷键；
  键盘玩家仍可按字母直接执行默认动作。
- 点击地面即可移动。寻路只经过已经探索、可通行的格子，
  对角线移动要求两侧正交格也可通行；自动路径会绕开已经见过的陷阱与液面，
  受伤或路径被挡会自动停下。
- 状态栏用等宽数字避免跳动，生命值低于一半转为琥珀色，低于四分之一转为红色；
  饥饿只在需要进食时才出现提示。
- 状态栏显示本局种子与当前层数；「转储」按钮导出种子、地图、状态、
  最近日志与存档 JSON，可复制或下载，便于反馈问题。

## 数据管线

```bash
bun tools/extract-nh-data.ts  /path/to/nethack   # 生成 monsters.gen.ts 与 objects.gen.ts
bun tools/extract-nh-roles.ts /path/to/nethack   # 生成 roles.gen.ts
bun tools/dump-level.ts 42 1 2 5                 # 输出指定种子与层数的 ASCII 视图
```

源码路径默认取环境变量 `NETHACK_SRC`，其次取项目根目录的上一级 `../nethack`。
生成结果提交进仓库，因此构建过程不依赖参考源码。

### 参考版本同步

数据对应的参考版本记录在 `tools/nethack-reference.json`：
分支 `NetHack-5.0`，提交 `c1b1b08`（2026-09-26），怪物 394 条、物品 441 条。

| 命令                  | 说明                                   |
| --------------------- | -------------------------------------- |
| `bun run sync:check`  | 检查参考仓库是否漂移，漂移时退出码为 1 |
| `bun run sync:record` | 记录当前参考版本（重新提取之后执行）   |
| `bun run sync:update` | 记录版本并重新提取数据                 |

上游更新后的完整流程与常见情况见 `docs/NETHACK-SYNC.md`。

### 模型素材

地牢中的门、楼梯与陷阱使用 Kenney 的 Mini Dungeon 模型；玩家与人形怪物使用
Mini 系列的人物模型（自带 idle/walk/attack/die 等 32 段骨骼动画）。
音效同样来自 Kenney（打击、脚步、开门、拾取、升级等 25 个）。
全部素材为 CC0，公共领域。
素材由脚本从素材库同步到 `public/assets/kenney/`，随仓库提交，
构建与运行不依赖素材库是否存在：

| 命令                   | 说明                                              |
| ---------------------- | ------------------------------------------------- |
| `bun run assets:sync`  | 从素材库同步模型（需要 `KENNEY_SRC` 或 `--src=`） |
| `bun run assets:check` | 校验仓库内素材与清单是否一致，已纳入 `verify`     |

清单 `public/assets/kenney/manifest.json` 记录来源、许可与每个文件的散列。
人物模型放在 `characters/`、音效放在 `audio/`，与地牢模型分开。
素材加载失败时渲染层会回退到程序化几何体，游戏仍可启动。

### Agent 反馈循环

项目内置了让自动化 Agent 自行测试与迭代的机制：确定性场景、不变量校验、
模糊测试、地图审计、快照回归、交互式观察通道与浏览器端到端检查。

| 命令                        | 说明                                                                          |
| --------------------------- | ----------------------------------------------------------------------------- |
| `bun run agent`             | 运行场景、模糊测试与地图审计，比对快照                                        |
| `bun run agent:json`        | 同上，输出结构化报告                                                          |
| `bun run agent:list`        | 列出全部场景                                                                  |
| `bun run agent:repl`        | 逐条命令观察游戏状态                                                          |
| `bun run agent:e2e`         | 浏览器端到端检查并截图；首次约 1 分钟，加 `--keep-browser` 后复用会话约 10 秒 |
| `bun run agent:e2e:preview` | 先构建再检查生产产物，开发与构建差异都在覆盖范围内                            |
| `bun run agent:smoke`       | 全流程冒烟：标题、创建、移动、背包、下潜、存读档、死亡、通关，并逐步截图      |
| `bun run verify:release`    | 发布前总检查：静态检查、自检、构建、反馈循环与生产产物端到端                  |
| `bun run verify:full`       | `verify` 与 `agent` 的完整校验                                                |

机制说明见 `docs/AGENT-LOOP.md`，Agent 操作契约见 `AGENTS.md`。

### 代码规范配置

- `.oxlintrc.json`：启用 TypeScript、unicorn、oxc、import 插件；correctness 记为错误，
  suspicious 与 perf 记为警告；`tools` 目录放宽未使用变量与命名遮蔽。
- `.oxfmtrc.json`：100 列、单引号、尾随逗号、LF 换行；生成的数据文件不参与格式化。
- `.gitattributes`：统一文本换行符为 LF，并把生成文件标记为可折叠。

提交前执行 `bun run verify:full`，它等价于持续集成中的完整校验。

## 日志与排查

日志默认只输出 warn 与 error。开启调试的方式：

- 访问 `?debug=1` 打开全部命名空间，或 `?debug=combat,fov` 只打开指定命名空间。
  带 `?debug=1` 时页面会暴露 `window.__nethack3d`，可读取会话状态与渲染开销。
- 访问 `?quality=low` 使用低质量档位：关闭抗锯齿并把像素比固定为 1，
  适合高分屏或集成显卡。
- 控制台执行 `localStorage.setItem('nethack3d.debug', 'combat')`。
- 运行时执行 `__nethack3dLog.enable('combat')`。

关键路径均有日志：关卡生成（含耗时）、视野计算、命中与伤害判定、
楼层切换、物品生成、存档读写、渲染网格构建、语言切换。
`__nethack3dDumpLogs()` 可导出最近 200 条日志文本，便于问题反馈。

```
src/
  core/      随机数（NetHack rn2/rnd/dice 语义）、瓦片常量、日志
  data/      生成的数据模块、中文名称表、查找辅助
  game/      关卡生成、视野、玩家、怪物、战斗、物品、背包、存档
  render/    three.js 场景、地牢/怪物/物品网格、程序化模型
  ui/        标题、角色创建、HUD、背包、物品名称渲染
  i18n/      语言包与运行时（t/tn、插值、复数）
tools/       数据提取脚本、自检、关卡预览
docs/        架构、流程与认知文档
```

## 已知边界

商店按十种专营种类铺货，价格随魅力浮动；钱不够可以赊账，离店结清，付不起就成了偷窃，店主会转为敌对。怪物特殊攻击已覆盖全部可生成的
原型；黏液与幻觉以短暂混乱代替，缓慢与加速已实际影响行动力，石化靠完全治疗药水解。
振动方块可在集齐三件开启圣物后开启传送门，渡过四层元素位面到星界登神；
元素位面已有虚空、岩浆、深水与浮空规则，土之位面还要求用镐挖穿地板前进。
宠物会随时间变饿，饿急了会变野；喂食能补回饱食度。宠物还没有自己的背包。
祝福与诅咒已生效，但还没有圣水祝福武器与献祭除咒。职业任务线已加入：
每个职业有自己的领袖、护卫、仇敌、五层任务楼层与专属对白，地图是通用布局，
没有逐职业复刻原版的 Lua 关卡与任务守卫拦截。
