# Agent 反馈循环

本页说明让 Agent 自行测试与迭代的机制：运行什么、观察什么、如何判断、怎么复现。
面向 Agent 的操作契约见根目录的 `AGENTS.md`，已知边界与工程约定见
`docs/COGNITION.md`。

## 目的

游戏逻辑改动的影响面很难靠阅读判断：一个数值调整可能让玩家卡死，
一个随机数用法变化可能让关卡无法复现。反馈循环把这些判断交给可执行检查，
让 Agent 在无人值守的情况下完成「改动 → 运行 → 读报告 → 修正」的迭代。

## 判定入口

| 层次   | 工具                       | 判定内容                                                             | 耗时量级   |
| ------ | -------------------------- | -------------------------------------------------------------------- | ---------- |
| 单元   | `bun run check`            | 随机数、数据完整性、战斗公式、存档往返等 1267 项断言                 | 约 15 秒   |
| 场景   | `bun tools/agent-loop.ts`  | 39 条确定性游戏路径，逐步校验不变量                                  | 2 秒       |
| 模糊   | 同上（`--fuzz=N`）         | 随机种子叠加随机行动（含使用、挥杖、投掷与神器启动），覆盖边角状态   | 随轮数增长 |
| 地图   | 同上（`--map-fuzz=N`）     | 批量生成关卡，用 ASCII 地图审计门的形状等静态结构                    | 约 1 秒    |
| 流程   | `bun tools/agent-smoke.ts` | 全流程走一遍：标题、创建、移动、背包、音效、下潜、存读档、死亡、通关 |
| 浏览器 | `bun tools/agent-e2e.ts`   | 真实页面渲染、界面交互、控制台错误、截图、分步耗时                   | 首次 76 秒 |

提交门槛 `bun run verify:full` 覆盖单元、场景、模糊、地图与快照；
流程与浏览器检查按需运行，发布前用 `bun run verify:release` 一并执行。

## 组成

```
tools/agent-lib.ts         会话构造、寻路、随机行动、状态快照、不变量、地图审计
tools/agent-scenarios.ts   场景库：启动、行走、下潜、战斗、吐息、呼救、逃跑、物品、商店、技能、设施、祈祷、神器、变形、许愿、宠物、骑乘、骨头、祝福、容器、矿坑、巫妖塔、投掷、特殊攻击、特殊楼层、饥饿、存档、终局、死亡、视野
tools/agent-golden.ts      关卡地形与战斗轨迹的快照采集与比对
tools/agent-loop.ts        主入口：编排、报告、产物
tools/agent-repl.ts        交互式观察通道
tools/agent-smoke.ts       全流程冒烟：逐步截图供人工复核
tools/agent-e2e.ts         浏览器端到端
tools/dump-level.ts        按种子与层数输出关卡 ASCII
tools/agent-golden.json    快照基准（随仓库提交）
tools/agent-artifacts/     运行产物：报告、失败现场、截图（已忽略）
```

## 不变量

不变量是判定的核心。任何一次行动之后，状态都必须满足：

- 玩家与怪物站在可通行格子上，坐标不越界，实体之间不重叠。
- 生命、法力、经验、金币、行动力在合法区间，死亡标记与生命值一致。
- 地面物品堆非空且位于可通行格子，装备槽指向的物品仍在背包中。
- 未付款的商店货品不在背包中，商店房间完整可通行且店主不离开店。
- 地形设施位于对应类型的格子上，且保持可通行。
- 阵营记录在 [-128, 127] 内，祈祷冷却非负，祭坛归属合法。
- 变形形态必须存在于怪物数据中，剩余回合非负。
- 上下行楼梯按规则存在，楼梯标记与瓦片类型一致。
- 迷雾只增不减，换层后自动重置基线。

不变量在 `tools/agent-lib.ts` 中实现，场景与模糊测试共用。
新增机制时同步补充，否则循环发现不了该机制的回归。

## 地图审计

关卡结构不会在行动中改变，因此单独用 ASCII 地图核对：`--map-fuzz=N`
按种子批量生成 N 层，逐扇门检查。期望值由 `auditDoors` 只从地图字符推导：
门必须一个轴两侧是通道、另一个轴两侧是墙，门板再垂直于通道。它不调用
渲染层与生成器共用的 `doorBlocksEastWest`，否则就是拿判定核对判定。
行动模糊测试很难碰到这一类静态缺陷，两层检查不能互相替代。

## 场景

场景是确定性的游戏路径，给定种子必然复现，因此失败可以直接重放。
默认用基础种子运行；用 `--seed=<n>` 抽查其它种子，场景与模糊应跨种子稳定。

## 快照回归

两类快照：

- **关卡地形**：5 个种子 × 6 个层数的地形、房间、门、陷阱、楼梯散列。
- **战斗轨迹**：2 个种子下固定属性的一场战斗，逐次攻击的结果序列散列。

散列相同说明行为未变，不同则说明关卡生成或战斗规则发生了改动。
确认改动符合预期后，用 `--update-golden` 更新基准，并在提交信息中说明原因。

## 失败现场

失败时产物目录会保存：

- `report.json`：完整结构化报告。
- `failures/<场景>.txt`：该场景的状态摘要与 ASCII 地图，玩家以 `@` 标记，怪物以字形标记。
- `failures/fuzz-<种子>.txt`：模糊测试失败时的现场。
- `failures/map-<种子>-d<层数>.txt`：地图审计失败时的关卡 ASCII。

这些文件足以在不重跑的情况下定位大多数问题；需要交互探查时用 `agent-repl`。

## 交互式观察

`bun run agent:repl` 维护一个会话，逐条命令返回 JSON：

```bash
printf 'new seed=7\nmove e\nmonsters\ninvariants\nmap 12\nquit\n' | bun tools/agent-repl.ts
```

可用命令：`new`、`move`、`wait`、`pickup`、`wield`、`wear`、`use`、`drop`、
`status`、`inventory`、`map`、`monsters`、`level`、`invariants`、`save`、`load`、`log`。

## 浏览器端到端

`bun run agent:e2e` 用 agent-browser 驱动真实浏览器，检查 35 项：
应用启动、调试句柄、画布与 WebGL、角色创建、进入会话、按键推进回合、
目标与情境操作、种子与层数、状态转储、画布命中与点击移动、悬停提示、
拖拽视角、背包菜单、门板位置与朝向、开门动画与锁闩、自动探索与休息、
渲染开销、素材加载、实时阴影、截图非空白、
触屏方向键（`?touch=1` 强制显示）与消息历史面板。

服务未启动时自动拉起；未安装 agent-browser 时输出 `skipped` 并以 0 退出，
因此纯逻辑开发不会因此受阻。

耗时几乎全在启动浏览器：页面打开一步约 72 秒，其余检查合计不足 5 秒。
迭代时加 `--keep-browser` 复用会话，再次运行降到约 9 秒：

```bash
bun tools/agent-e2e.ts --keep-browser   # 会话保留，随后的运行秒级完成
agent-browser --session nh3d-e2e close  # 收尾时关闭会话
```

冒烟测试按真实玩家的顺序走完整局，每一步都留下截图（`tools/agent-artifacts/smoke/`）。
它负责发现「单点检查都通过、连起来用却不对」的问题，也是界面改动的视觉复核入口。

鼠标相关的检查一律使用真实鼠标事件（`agent-browser mouse move/down/up`），
不使用页内合成事件：合成事件绕过命中测试，无法发现覆盖层挡住画布的问题。
其中「画布可接收点击」直接用 `document.elementFromPoint` 断言命中元素。

报告中的 `metrics.render` 记录绘制次数、三角面、程序数与像素比，
可用于对比渲染改动的开销。脚本会先确认端口上服务的类型：
发现开发服务器与生产产物不匹配时直接失败，不会把两者混淆。

默认检查开发服务器。加 `--preview` 会先构建再用 `vite preview` 提供产物，
覆盖只在构建期生效的环节（压缩、摇树、相对路径、分包），两种模式跑同一组检查。

## 扩展方式

- 新增机制：在 `checkInvariants` 补充不变量，在场景库补充覆盖路径。
- 新增场景：按 `agent-scenarios.ts` 内的约定实现，并注册到 `SCENARIOS`。
- 新增快照：在 `agent-golden.ts` 中扩展采集集合，然后 `--update-golden`。
