# 认知文档

本文件记录项目的当前认知：目标、决策、状态快照、参考事实、风险、已知边界、
工程约定与下一步。架构细节见 `docs/DESIGN.md`，使用方式见 `README.md`。

## 项目目标

在浏览器中实现三维 NetHack，满足以下约束：

- 参考实现为本地 NetHack 5.0 C 源码，数据由脚本提取，不凭记忆编写。
- 技术栈为 Bun、TypeScript、Vite 与 three.js，静态检查使用 oxlint 与 oxfmt。
- 玩法为回合制 roguelike：地牢生成、战斗、物品、鉴定、法术、饥饿、角色创建与存档。
- 界面支持英文与简体中文，运行时切换。
- 关键路径有日志，便于排查。
- 文档与注释使用简体中文。

## 关键决策

| 决策                                             | 理由                                       |
| ------------------------------------------------ | ------------------------------------------ |
| 数据从 C 头文件提取并生成带类型的模块            | 数据可核对、可复现，构建不依赖参考源码     |
| 关卡由 `(seed, depth)` 确定性生成                | 存档只需保存种子，体积小且稳定             |
| 游戏逻辑与语言解耦，消息只存键与 ID              | 切换语言后历史消息也能重新翻译             |
| 地牢设施与人物使用 Kenney 素材，其余程序化生成   | 表现与体积平衡，素材缺失可回退             |
| 随机数沿用 NetHack 语义                          | 便于与原版概率对照，行为可预期             |
| 商店位置与货品使用派生随机流                     | 商店改动不扰动其它楼层的地形与陷阱         |
| 地形设施用情境动作而非踏入自动触发               | 喝泉水、坐王座应由玩家决定，避免踩中即生效 |
| 严格模式 TypeScript，`tsc --noEmit` 作为提交门槛 | 类型即文档，减少运行时错误                 |
| 日志默认只输出 warn 与 error                     | 避免刷屏，需要时用 `?debug=1` 打开         |
| 护身符带回第 1 层才算通关                        | 给终局一段撤离路程，巫师追杀增加紧迫感     |

## 参考事实

以下结论已通过阅读源码或运行脚本确认：

- `include/monsters.h` 有 394 条 `MON(` 条目，条目格式为
  `MON(NAM/NAMS(...), S_*, LVL(等级,速度,护甲,魔抗,阵营), (G_*|频率), A(ATTK(...)×6), SIZ(...), MR1, MR2, M1.., M2.., M3.., 难度, CLR_*, TAG)`。
- 护甲字段的含义是 `10 - 加成`，例如板甲 `ac = 3` 对应 7 点防护。
- 法术书等级存放在 `OBJECT` 的第 12 个参数，未鉴定外观在类别内洗牌决定。
- 命中公式位于 `uhitm.c` 的 `find_roll_to_hit()` 与 `mhitu.c`；
  负护甲通过 `AC_VALUE` 随机化并减免伤害，而不是免疫攻击。
- 怪物难度窗口来自 `include/monst.h`：下界 `depth / 6`，上界 `(depth + 玩家等级) / 2`；
  `G_HELL` 怪物从第 25 层（大墓地起）进入生成池。
- 初始属性使用 `init_attr(75)` 与按职业分布重分配的点数机制。
- 三件开启圣物的出处与 `makemon.c` 一致：开启之铃由任务仇敌（`MS_NEMESIS`）携带，
  祈祷烛台由弗拉德携带（本作用巫妖塔首领代替），死亡之书在圣所；
  物品 id 是 `SPE_BOOK_OF_THE_DEAD`，不是 `BOOK_OF_THE_DEAD`。
- 圣所的振动方块在原版里开启通往圣所的楼梯；本作把它改成通往异界的传送门，
  因为护身符已经放在第 30 层，不需要再开一道下行楼梯。

## 风险与对策

| 风险                             | 对策                                                         |
| -------------------------------- | ------------------------------------------------------------ |
| C 宏解析脆弱，存在嵌套括号与续行 | 平衡括号分词器、字符串感知的参数替换，外加条目数量与抽样断言 |
| 生成算法的改动会破坏旧存档       | 存档只存种子与可变状态，几何重建；生成器改动需更新快照基准   |
| 渲染性能随实例数量下降           | 按类型批量实例化，仅重建变化的地面物品堆                     |
| 规则复杂度高，难以一次实现完整   | 按优先级分批交付，未实现部分明确写入已知边界                 |

## Agent 反馈循环

项目内置让 Agent 自行测试与迭代的机制，详见 `docs/AGENT-LOOP.md`：

- `bun run agent` 运行 37 条确定性场景、模糊测试与地图审计，并比对快照；
- 不变量覆盖位置、数值、实体唯一性、装备一致性、楼梯与迷雾单调性；
- `auditDoors` 从 ASCII 地图核对门满足「前后是通道、两侧是墙」，再核对门板朝向；
- 失败时输出复现命令与现场快照（地图 + 状态），产物在 `tools/agent-artifacts`；
- `bun run agent:repl` 提供逐条命令的 JSON 应答，便于交互探查；
- `bun run agent:e2e` 用真实浏览器检查渲染与界面，产出截图。

新增机制时应同步补充不变量与场景，否则循环发现不了该类回归。

## 已知边界

- 宠物会随时间变饿：饱食度降到 100 会抱怨，归零后变野（坐骑会先落地）；
  喂食恢复饱食度、生命与驯服度。宠物还没有自己的背包。
- 祝福与诅咒已生效（圣水、诅咒之水、药水/卷轴/魔杖强度、诅咒装备取不下来）；
  祝福祈祷会解除装备上的诅咒。
- 附魔卷轴沿用原版的软上限：护甲超过 +3（精灵甲与巫师冠 +5）、武器超过 ±5
  再附魔会直接蒸发；附魔收益随强度递减，+9 以上的武器只有小概率再进一步。
- 工具里魔法灯、镐、毛巾、独角兽角、听诊器、水晶球、记号笔、罐装油脂、蒙眼罩、
  镜子、相机、魔哨、乐器（号角喷吐息/催眠/惊退、丰饶角、地震鼓、普通乐器吵醒）、
  灯具（点亮房间）、牵引绳（拴住宠物）与塑像（放出封着的怪物）均有实际用途。
- 骨头文件只保留最近一份，取出遗物后即清空，不会反复出现。
- 粒子已有命中火花、死亡爆散与火把飞灰；玩家与怪物投射实时阴影，火把只照明。
- 武器与法术流派熟练度都按使用次数自动成长；没有技能槽与手动分配。
- 陷阱已能触发伤害、定身、睡眠、传送、掉层、腐蚀、变形与雕像活化；
  圣所固定放一块振动方块，集齐开启之铃、祈祷烛台与死亡之书（都未受诅咒）
  并在方块上举行仪式，即开启通往异界的魔法传送门。
- 终局是一段五层流程：土、气、火、水四层元素位面加星界位面。
  土之位面是大地元素与石魔，没有下行楼梯，必须拾起地上的镐向下挖穿地板；气之位面散布虚空并放风元素与雾气，
  火之位面散布岩浆（踩上去会被灼伤，火焰抗性减半），且整层热浪每回合
  灼伤没有火焰抗性的玩家；水之位面散布深水
  （不会游泳又没有浮空会溺水掉血），星界是大厅加三座阵营祭坛、
  天使（每座祭坛两位：同阵营平和、异教敌对）与三名天启骑士。虚空可以靠浮空越过；挖掘已有雏形，但完整飞行规则还没做；
  天启骑士的瘟疫（`AD_PEST`）会让玩家生病、饥荒（`AD_FAMN`）额外消耗饱食度，
  两者另外照常造成伤害；死亡的 `AD_DETH` 在原版对玩家也只有骰子伤害。
- 怪物特殊攻击已覆盖全部可生成的 `AD_*`：元素、状态、吸能吸级、锈蚀、
  偷窃与诱惑、诅咒、去附魔、取消、缠绕、分解与石化均有结算；
  失明或戴蒙眼罩时躲得过目光攻击（美杜莎的石化目光、浮游眼的麻痹）。
- 没有对应机制的局部简化：黏液与幻觉以短暂混乱代替；
  加速与缓速已实际改变怪物的行动力累积（倍数与计时见 `monsterSpeed`）；
  变形只借用怪物的护甲、近战骰与抗性，没有额外生命池与体型判定；
  石化靠完全治疗药水解；吃鸡蛇类尸体（无石化抗性）会立即石化死亡，没有蜥蜴尸体；
  不可生成的独特怪物（死亡触碰、瘟疫等）
  仍按物理伤害结算。
- 尸体从击杀掉落，吃掉可获得怪物 confers 里的内在抗性；尸体带形成回合，
  放久后会腐坏致病（疾病状态：停止回复并周期性掉血，祈祷与完全治疗药水可解）；
  浮游眼等怪物的尸体会赋予心灵感应，会传送的怪物尸体会赋予传送症；
  ESP 护身符与心灵感应头盔装备时也提供感应；
  罐头需要开罐器或武器，内容按层数抽取，偶尔变质；尸体不会自行消失。
- 商店有十种专营种类，按各自库存表铺货，价格随魅力浮动；钱不够可以赊账，
  离店（或换层）时结清；付不起就成了偷窃，店主转为敌对并扣阵营记录；
  和平的店主在受挑衅前不还手，但会主动让开门口（对应原版 `shk_move` 的
  avoid 分支），不会把唯一的入口堵死。
- 现代 roguelike 的便捷操作：自动探索（`x`）反复走向最近的未探索边界，
  视野里出现敌人、受伤或尝试次数超限时停下；休息（`R`）原地等到生命与
  法力回满，挨打、生病、饥饿或超过 600 回合时停下；状态栏可以开关
  自动拾取，走过地面堆时顺手带走物品（未付款的商店货物除外）。
- 悬停可见怪物会显示名字、伤势档位与剩余生命百分比（可疑的拟形怪除外），
  相邻时情境操作栏的攻击按钮也带同样的伤势提示。
- 门可以带机关：深层的关闭门有 1/25 概率带机关，开门时触发一次
  （箭矢、飞镖、落石、火焰、催眠气体或同层传送），之后失效；
  搜索可以发现门上的机关，悬停会标出「有机关的门」，已知的机关
  可以用拆陷阱动作解除。
- 地形设施与祭坛都可互动；祈祷有冷却与阵营记录，献祭可用尸体换取幸运，
  或让异教祭坛归附；祭坛上的水会随祈祷变成圣水或诅咒之水；祝福祈祷还能除咒。
- 职业任务线是通用五层布局：总部有领袖与护卫，搜索层有额外护卫与金币，
  目标层是大厅中央一间带门的石室（仇敌巢穴），仇敌与神器守在室内；穴居人、野蛮人、游侠、女武神与武僧的总部是露天营地/洞穴（大房间），
  其余职业是室内多房间；13 个职业各有自己的领袖、仇敌、地名、神器与对白
  （简报、答谢与仇敌叫阵），地名与对白都在语言包中。
  未获领袖许可前，总部的下行楼梯、地洞、向下挖、楼层传送与神器传送都被
  神秘力量挡住（对应原版 `ok_to_quest()`）；杀了领袖也会解封，但任务无法再复命。
  仇敌的爪牙把守巢穴门口；打任务领袖或护卫会让整个总部翻脸。
  没有逐职业的 Lua 关卡。
- 分支地牢已有矿坑（第 4 层进入，8 层，侏儒与矮人主题，底层是矿镇市集）、巫妖塔
  （第 16 层进入，4 层，不死主题，底层有仇敌与财富）、职业任务（第 14 层进入，5 层：
  总部、搜索层与目标层）、卢迪奥斯要塞（第 18 层进入，1 层，克罗伊斯与守军守着金币）
  与推箱（神谕所链入，4 层，从底层进、顶层拿奖励）。
- 推箱分支用 `dat/soko*.lua` 提取的固定地图：4 层各两个变体，巨石、坑洞、门、
  楼梯与奖励位置都照搬原版；巨石可推动、推进洞里会连洞一起消失。
  顶层两只巨型拟形怪伪装成巨石，撞上去才现形；推箱层禁止传送（陷阱、卷轴与
  传送症都被神秘力量挡下）；用力场法术轰碎巨石会扣一点幸运，镐类工具与
  挖掘魔杖也拆不动推箱层的墙。
- 特殊楼层已有大房间（5 层）、神谕所（8 层）、美杜莎（20 层）、大墓地（25 层）、
  要塞（27 层）与圣所（29 层）；职业神器改在任务目标层仇敌脚下发放。
- 怪物状态新增定身与被取消：定身魔杖冻结目标若干回合，取消魔杖
  抹掉目标的非物理特殊攻击（近战与被动攻击里都不再生效）。状态随存档保留。
- 怪物会避让危险地形：不会游泳又不会飞的怪物不主动下水，没有火焰抗性的
  怪物不踏进岩浆；水元素、火抗怪物与原版水生怪物照常通行。
- 会收集物品的怪物（`M2_COLLECT`，如地精与兽人）走过地面堆时
  会带走金币与小件物品（最多三件），玩家看得见时会有提示；
  商店里的货物不碰，怪物死亡时携带的物品掉回脚下；携带列表随存档保留。
- 怪物开门沿用原版规则：有手且不小的怪物推开普通门，变形怪从门缝下钻过，
  巨型怪物砸开上锁的门；没手、太小或碰上锁门的怪物被挡在门外。
- 怪物也会踩中陷阱：伤害、定身（捕兽夹、蛛网）、睡眠气体、同层传送、
  地洞与楼层传送、变形与魔法陷阱都对怪物生效，被陷阱打死的怪物
  不计入玩家击杀与经验；飞行的怪物从地面陷阱上方掠过。
  看见陷阱触发的怪物会记住这类陷阱并绕开（对应原版 `mons_see_trap()` 与
  `mon_knows_traps`，动物、无智与无眼的怪物不记）。
- 挖掘：持握镐向同一面墙移动要连续三回合才能凿穿（矮人锹两回合），中途挪开则
  重新计时；持镐站在地面上还可以选「向下挖」，三回合后在原层留下地洞
  并落到下一层。每次挥镐与踢门都会发出噪音，按原版 `wake_nearby()` 的
  半径唤醒附近沉睡的怪物；凿穿商店外墙要赔 10 × 力量的修缮费，
  在商店地板上开洞赔 200，离店时与货款一起结清，付不起则店主翻脸。
  挖过的瓦片与进行中的挖掘进度都随存档保留；推箱层一律禁止挖掘。
- 浮空已有完整来源与效果：浮空药水计时、浮空戒指、浮空靴让人飘起来，
  可以越过虚空（气之位面的障碍）与岩浆/水流，不触发地面陷阱（魔法传送门例外），
  但浮空够不着楼梯、也挖不动地板；飞行护身符（FLYING）效果相同但能正常上下楼梯。
  计时与浮空状态随存档保留。
- 深水会溺水：站在水中且不会游泳又没有浮空时，每回合受伤并累积溺水状态；
  浮空、两栖或会游泳的形态都能免除，离开水面后计数归零。
- `role.c` 的 `struct Role` 依次给出 mnum、petnum、ldrnum、guardnum、neminum、
  enemy1num、enemy2num、enemy1sym、enemy2sym、questarti；提取脚本按这个顺序
  读出 13 个职业的任务领袖、护卫、仇敌、地名与前缀，并验证怪物 id 存在。
- 反馈循环的模糊测试会跨种子扫描（至少 13 个种子 × 8—12 轮）；
  发现过同一件戒指占两个槽位、仪式惊醒的恶魔当场打死测试角色、
  测试辅助把玩家放到怪物身上这类问题；修复要写成自检断言，
  场景辅助（如 `teleportPlayer`）也必须自己维持实体不重叠的不变量。
- 惩罚卷轴已有完整效果：读卷轴招来锁在脚踝上的铁球，受罚期间隔一回合
  才能移动，铁球也丢不掉；向神祈祷（祝福或回应）可以打碎镣铐。
  铁球数据由 BALL_CLASS 提取，不参与随机生成。
- 完整的内容对照与优先级见 `docs/CONTENT-PLAN.md`。

## 工程约定

数据与生成：

- 宏替换必须跳过字符串字面量，否则 `FOOD("tin", ..., METAL, ...)` 中的
  `tin` 会被参数值替换，产生错误数据。
- 引用数据里的 id 前先确认它存在：职业 id 是 `CLERIC`/`BARBARIAN` 这类抽取结果，
  不要凭记忆写 `PRIEST`/`WARRIOR`。
- 走廊用「格子加进入方向」为状态的最短路，转弯加价，长直线优先；
  房间外圈（含四角）是走廊禁区，靠房间间距腾出车道，保证连通。
- 形态问题回到生成端处理。门由生成器保证「前后是通道、两侧是墙」，
  渲染与判定只消费这个形状，不在下游打补丁。
- 表驱动的效果比逐类型写分支好维护：新增陷阱类型是加一行数据，不是加一段逻辑。

检查与报告：

- 用同一份判定核对判定等于没核对。期望值要从独立数据源推导，
  例如门审计只读 ASCII 地图，不调用 `doorBlocksEastWest`。
- 不变量要覆盖派生视图与状态的一致性。只检查「可见瓦片是否被记忆」
  会漏掉视野未重算的情况；加上「玩家所在格必须在视野内」才能捕获该类回归。
- 断言不要用容错值掩饰失败。`Number(值 ?? -1)` 在字段缺失时反而成立，
  会让检查变成假通过；读不到数字就应当直接判失败。
- 存档往返测试覆盖属性、背包、装备、迷雾与怪物，
  任何遗漏都会在继续游戏时暴露。
- 报告类输出先补齐派生字段再写盘，否则终端显示正常而产物缺字段。
- 自动化脚本必须校验「测的是哪个服务」，残留的服务会让生产产物检查
  悄悄连上开发服务器并全部通过。
- 校验命令不要直接接管道：`bun run verify:full | grep …` 的退出码来自 grep，
  失败会被 `&&` 链条吞掉；输出重定向到文件后再检查退出码。
- 冒烟脚本少做调试式操作：按两次 Esc 会退回主菜单，
  后续步骤便跑在已停止的会话上。
- 让新机制真正致命之后，既有测试可能变得不稳定；
  测试要对「提前阵亡」这类路径同样成立。

渲染与素材：

- 门扇、锁闩与破门都由 `DungeonMesh.update()` 每帧从 `level.doors` 读回状态：
  只在建网格时取快照，会让开门后的模型一动不动。
- 视野必须在移动后立即重算，否则渲染使用上一格的可见性。
- 在 `update()` 里加提前返回要格外小心：一处 return 可能跳过
  地牢与相机更新，画面全黑而单元测试全绿。
- 蒙皮网格必须用 `SkeletonUtils.clone` 复制，普通 `Object3D.clone` 不会重绑骨骼。
- 人物模型的贴图要与模型保持相对目录结构，glTF 里的贴图路径相对于模型文件。
- glTF 贴图的 UV 约定是 `flipY = false`，而 `TextureLoader` 默认 `true`；
  混用时 V 坐标翻转，采样落到图集空白区，模型整片发黑且不报错。
- 外部素材要按「可校验、可回退」设计：清单记录散列并纳入 verify，
  加载失败时回退到程序化几何体。
- 性能优化先量再改，方向由数据决定：几何侧压力小，开销主要在填充率。

交互与界面：

- 合成事件会绕过命中测试，自动化交互必须用真实鼠标事件，
  并用 `document.elementFromPoint` 断言最顶层元素；
  探针点要避开操作按钮区域，点位扫描先确认最顶层是画布。
- 全屏覆盖层的指针事件要逐元素指定，按容器写的规则会同时影响 HUD 与弹窗。
- 界面元素要能点得动才给出来；文案不复用提问式模板，动作按钮单独准备标签。
- 触屏方向键只在粗指针设备显示；自动化用 `?touch=1` 强制打开，
  才能在没有真实触屏的环境里验证按键与回合推进。
- 打开面板时要收起光标浮层，这类残留只有截图才能发现。
- 视觉问题先量数值（相对偏移、包围盒）再看截图；
  明显异常先画成 ASCII 并统计，比盯着效果图猜快得多。

环境：

- 一个进程内首次调用 git 约 10 秒（冷启动），之后约 0.1 秒；
  高频路径直接解析 `.git/HEAD` 与文件散列，避免子进程。
- 浏览器首次启动约 72 秒，固定会话名并复用可降到约 9 秒。
- `bun:test` 启动约 0.2 秒；覆盖率门槛按全局百分比判定，取值在 0 到 1 之间。
- Bun 原生接口可直接替换 Node：`Bun.write` 自动创建父目录，
  `Bun.CryptoHasher` 与 `node:crypto` 结果一致，`import.meta.dir` 取代
  `fileURLToPath(import.meta.url)`。
- Windows 上用 `sed -i` 改文件有概率留下空文件（MSYS 替换失败）；
  文档改动优先用编辑工具，避免 shell 原地重写。
- Windows 上杀子进程要认准真身：套一层 `bun run` 或批处理壳时，
  `kill` 只杀得掉包装进程；直接运行 `node_modules/vite/bin/vite.js` 才能干净结束。
