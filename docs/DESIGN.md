# 架构说明

本页说明模块划分、数据流与关键取舍。已知边界与工程约定见 `docs/COGNITION.md`。

## 目标

1. 忠于原版数据。怪物、物品、职业、种族与战斗公式来自 NetHack 5.0 源码，
   不做凭记忆的重写。
2. 三维表现以程序化几何体为主。门、楼梯、陷阱与人物使用 Kenney 素材（CC0），
   素材缺失时回退到程序化几何体，游戏仍可启动。
3. 文案与语言解耦。游戏逻辑只产生消息键与实体 ID，所有可见文本经由 `src/i18n` 渲染。
4. 状态与渲染分离。游戏状态是可序列化的普通对象，渲染层只是它的投影加动画。

## 数据流

```
键盘 / 界面输入
      │
      ▼
game/session ──► 状态变更（玩家、怪物、物品、回合）
      │                 │
      │                 ├─► 消息键 + 实体 ID ──► ui/hud ──► i18n ──► 屏幕文本
      │                 │
      ▼                 ▼
render/scene ◄── 可见性、网格同步 ──► three.js 场景
```

游戏逻辑不直接读写 DOM，也不拼接可读文本；这样切换语言只需重绘界面。

## 关卡生成

参考 `src/mklev.c` 的流程：

1. 随机放置互不重叠的房间：宽 2 到 12、高 2 到 6、面积不超过 50，
   房间之间留 3 格间距。两侧各一格作墙体，中间一格留给走廊，
   走廊因此不会贴着房间走，房间侧面也不会被凿出缺口。
2. 每间房就近接入已连通的走廊网络，再补充若干随机连接，避免地图退化成树。
3. 每条走廊用「格子加进入方向」为状态的最短路开挖：转弯加价 0.35，
   房间内部与房间外圈不可穿越。于是路线倾向长直线，拐弯集中在少数几处，
   与原版走廊的观感一致。
4. 开口取在双方正对的一面并对准目标，走廊因此接近直线。
   门外一格是走廊起点，门位在落成前校验；规范化时去掉相邻的门，
   保证每个房间都有入口。
5. 计算墙体朝向，再布置上下楼梯、陷阱与喷泉、水槽、祭坛、坟墓、王座等设施。

每扇门都满足同一个形状：**一个轴的两侧是通道，另一个轴的两侧是墙**。
门位取在房间外圈，门口方向与房间外墙垂直，门外一格才是走廊起点；
挖走廊时把「房间外圈（含四个角）」当作不可穿越，因此走廊不会蹭到门的两侧，
也不会把房间侧面凿出缺口。房间之间至少留 3 格，中间一格正好是走廊。
判定抽成 `doorBlocksEastWest`：通道在东西向就拦东西向，渲染层据此决定门板朝向。

门位在落成前由 `doorShapeOk` 校验；规范化时会封掉不合规或相邻的门，
并给没有入口的房间补一段走廊。期望值由 `tools/agent-lib.ts` 的
`auditDoors` 只读 ASCII 地图独立推出：先核对「前后通道、两侧墙」，
再核对门板朝向；自检的「地图结构」分组与 `--map-fuzz` 都跑这套审计。

门板位置：转轴在格子边缘，`panel.position` 是相对转轴的偏移，
因此写成半格（0.47）才能让闭合的门落在格子中央；写成
「半个门板长度减去半格」会让整扇门偏出半格。这条有端到端断言守着：
逐扇检查闭合门的世界坐标与该格中心的距离。自检的「地图结构」分组
锁住以下性质：门不与其他门相邻、门表与瓦片一致、每个房间都有门、
门都满足「前后是通道、两侧是墙」、房间矩形内不出现走廊；
端到端再量一遍闭合门板的包围盒长轴。

关卡几何完全由 `(gameSeed, depth)` 决定，随机数流与其他系统隔离，
因此存档只需保存种子即可重建地形。

## 巨石

巨石是地面物品里的特例：不可拾取；玩家朝它移动时，若身后一格可通行、
无怪物也无第二块巨石，就把巨石推到那一格并自己走进空出的格子。
推不动时玩家原地不动且不消耗回合。矿坑与后续的推箱关卡用它做障碍物；
怪物寻路暂不绕开巨石。

## 陷阱

陷阱在踩中时结算。每种陷阱归到少数几种效果类型，新增类型只是往
`game/traps.ts` 的表里加一行：

| 效果类型      | 处理                           | 覆盖的陷阱                                   |
| ------------- | ------------------------------ | -------------------------------------------- |
| damage        | 掷骰扣血                       | 箭、飞镖、落石、坑、尖刺坑、地雷、火焰、巨石 |
| hold          | 掷骰扣血并定身                 | 捕熊夹、蛛网                                 |
| sleep         | 睡眠若干回合                   | 催眠气体                                     |
| drainPw       | 法力清零                       | 反魔法力场                                   |
| wake          | 唤醒全场怪物                   | 吱嘎板                                       |
| rust          | 磨损所穿盔甲的附魔             | 腐蚀陷阱                                     |
| teleport      | 传送到本层随机地面             | 传送陷阱                                     |
| levelTeleport | 随机换层                       | 层级传送陷阱                                 |
| hole          | 掉到下一层                     | 陷坑                                         |
| magic         | 伤害、治疗、抽法力或传送四选一 | 魔法陷阱                                     |
| polymorph     | 变成随机怪物形态               | 变形陷阱                                     |
| statue        | 生成一只敌对怪物               | 雕像陷阱                                     |
| flavor        | 只给提示                       | 振动方块                                     |

沉睡或定身期间无法移动，但回合照常流逝，怪物会继续行动。
陷阱在踩中之前不可见：渲染只看陷阱自己的发现标记，不再随地形一起暴露。
圣所（第 29 层）固定放一块振动方块：它有专属提示，但还没有开启传送门的机制。

## 地形设施

喷泉、水槽、坟墓、王座各有一个情境动作，站在设施上时界面给出按钮：

| 设施 | 动作   | 效果（按权重抽取）                                             |
| ---- | ------ | -------------------------------------------------------------- |
| 喷泉 | 喝水   | 治疗、回法、幸运、力量、看见隐形、干涸、水恶魔或水蝮蛇现身     |
| 水槽 | 踹一脚 | 溅水、捞出物品、惊动全层、砸碎水槽、黑布丁出现                 |
| 坟墓 | 挖掘   | 金币、物品、惊动亡者、阴风减运；挖开一次就到底                 |
| 王座 | 坐下   | 治疗、回法、力量、金币、物品、电击、惊动全层、消失；只灵验一次 |

效果表在 `game/features.ts`，与陷阱表同构：效果归到少数几种类型，
会话层按类型执行。设施状态存在 `FeatureState` 的 `depleted` 与 `used` 上，
随存档保留；消失或碎裂的设施把瓦片恢复成普通地面。
祭坛没有情境动作表条目，它的用途是祈祷与献祭，见下一节。

## 祈祷、献祭与阵营

- 阵营记录随玩家数据保存，范围 [-128, 127]，显示在状态栏。击杀敌对的对立
  阵营加分，击杀同阵营与和平生物扣分，祈祷受罚与献祭失误也会扣分。
- 祭坛在生成时确定归属：四分之一属于无阵营神坛（摩洛克），其余随机归三神之一。
  归属用 `deriveSeed(gameSeed, 'altar', depth)` 的独立随机流，不扰动其它设施。
- 祈祷（快捷键 `p`）的结果分四档：
  - 祝福：站在自己阵营的祭坛上且记录不为负。满血满法，清除失明、混乱、
    眩晕、定身与石化，阵营记录 +1。
  - 回应：有祭坛但归属中立，或没有祭坛而记录不为负。回复一半生命与法力，
    同样清除异常状态。
  - 无回应：没有祭坛且记录为负。
  - 震怒：祈祷冷却未过，或站在别的阵营的祭坛前。受伤、阵营记录 -5，
    一名敌对天使降临执行神罚。
- 每次祈祷都重置冷却：正常 300–600 回合，受罚 500–800 回合。
- 祝福结果还会解除身上装备的诅咒（`uncurseEquipment()`），对应原版祈祷的
  “解除麻烦”分支。
- 把水放在祭坛地面再祈祷：同阵营且记录不为负时变成圣水，其它情况变成诅咒之水，
  对应 `pray.c` 的 `water_prayer()`；水不必带在身上。
- 站在祭坛上且背包里有尸体时，界面会给出「献祭」动作：
  - 无主祭坛（摩洛克）只吞掉祭品，不给回报。
  - 同阵营且祭品足够强壮（怪物等级 + 3 不低于玩家等级）时，幸运 +1、
    阵营记录 +3；太弱的祭品没有效果。
  - 异教祭坛有 35% 概率被本神收服（归属改成玩家阵营），否则阵营记录 -3。

## 变形

变形把玩家换成怪物形态，来源有三种：变形药水、变形陷阱与怪物的变形攻击
（`AD_POLY`）。佩戴不变护身符时全部被挡住。

- 形态只记录怪物原型 id 与剩余回合（20–39），属性按需从数据查回：
  护甲等级改用怪物的 `ac`（戒指等临时加值仍生效），近战使用形态的第一组
  有效骰子，抗性来自怪物的 `MR_*` 列表；到期自动恢复原形。
- 变形期间不显示手持武器，攻击消息按徒手处理。
- 简化：没有 NetHack 那样独立的怪物生命池、体型判定与解除变形时的位置检查。

## 许愿

许愿由许愿魔杖（`zap`）与魔法灯（`apply`）触发：使用后记下一次待处理的愿望，
界面弹出输入框，输入文字后兜现。

- 匹配顺序：内部 id、英文全名（补上 `potion of` 这类类别前缀）、中文名，
  最后是长度足够的子串；支持「2 potions of healing」这样的数量前缀（1–10）。
- 「gold」或「金币」给出一堆金币；唯一物品与任务神器不在许愿池内。
- 匹配不到时不消耗愿望，面板保持打开让玩家重试；背包放不下时物品落在脚下。

## 宠物

开局按职业获得一只宠物（骑士得小马，法师与治疗师得小猫，其余得小狗）：

- 宠物带 `tame` 标记，不攻击玩家；玩家撞到它时双方交换位置，寻路也把宠物
  当作可通行，避免被堵在走廊里。
- 宠物行动：身边有敌对生物就攻击（怪物之间的命中公式在 `combat.ts`），
  否则朝玩家移动；和平生物（店主、守卫）不在攻击之列。
- 换层时原层的宠物被带到新层玩家身边，放不下时留在原层。
- 攻击自己的宠物会让它失去信任；宠物死亡有独立提示。
- 喂食：宠物在玩家身边且背包里有食物时出现「喂食」按钮，消耗一份食物，
  恢复一半生命并提高驯服度；驯服度满值后成长一次（小猫→大猫、
  小狗→狗、小马→战马）。
- 骑乘：身边的中大型驯服宠物（小狗、小马等）可以骑上，坐骑暂时离开地图，
  攻击时追加坐骑天然骰的冲锋伤害；下马时坐骑回到身边空地。坐骑随存档保存。
- 简化：没有饥饿变野与宠物背包。

## 特殊楼层

固定深度绑定固定内容，定义在 `game/special.ts`，与普通楼层一样由种子复现：

| 深度 | 标识       | 内容                                         |
| ---- | ---------- | -------------------------------------------- |
| 5    | `big_room` | 一整间无门大厅，怪物数量上调                 |
| 8    | `oracle`   | 保证出现神谕，额外 3 座喷泉                  |
| 20   | `medusa`   | 保证出现美杜莎（石化碑眼），散落 6 座雕像    |
| 25   | `valley`   | 怪物主题限定为不死生物，额外 4 座坟墓        |
| 27   | `castle`   | 保证出现士兵、军士、中尉与上尉，必有许愿魔杖 |
| 29   | `sanctum`  | 怪物主题限定为恶魔，额外 2 座坟墓            |

- 布局变体在生成阶段接管房间与走廊；保证出现的怪物与雕像在进入楼层时放置，
  怪物放在至少 8 格外，避免一进层就被石化。
- 额外坟墓避开门口，否则 `|` 字形会被地图审计误读为墙。
- 进入特殊楼层时会打出楼层名（`special.*` 文案）。
- 神谕所：站在神谕旁边会多出「咨询」按钮，花 20 枚金币换一条关于本作
  机制的提示（`oracle.tip*` 文案）；付不起时不消耗回合。

## 骨头文件

玩家死亡时把现场写成一份骨头文件（`game/bones.ts`）：记录死亡层数、角色与
背包物品。下一局进入同一深度时会发现遗物，并有一只幽灵看守；取出后清空，
不会反复出现。

- 浏览器用 localStorage，测试环境退回进程内存，接口一致。
- 物品编解码在 `game/itemcodec.ts`，与存档共用。
- 只在有记录时才消耗随机数，所以没有骨头文件的局面不受影响。

## 分支地牢

分支从主地牢的固定楼层进入，有独立层号与随机流。定义在 `game/branches.ts`：

| 分支     | 入口  | 层数 | 主题                                                     |
| -------- | ----- | ---- | -------------------------------------------------------- |
| 矿坑     | 4 层  | 8 层 | 侏儒与矮人为主，底层是矿镇市集（必有商店、喷泉与幸运石） |
| 巫妖塔   | 16 层 | 4 层 | 不死生物为主，底层有吸血鬼首领与额外物品                 |
| 职业任务 | 14 层 | 5 层 | 内容随职业变化，首层是总部，底层是仇敌与神器             |
| 卢迪奥斯 | 18 层 | 1 层 | 克罗伊斯与一队士兵守着大额金币与宝石                     |
| 推箱     | 8 层  | 4 层 | 原版 `dat/soko*.lua` 固定布局，从底层进入，顶层有奖励    |

- 入口层多一段「分支楼梯」（`StairRef.dir = 'branch'`），用独立随机流选位置，
  不扰动本层的陷阱与设施；走上它进入分支第一层，分支第一层的上行楼梯
  回到入口层的同一段楼梯。
- 关卡键在主地牢是层号，在分支是 `分支:层号`；存档同时保存两边。
- 分支底层的怪物难度按层数补偿，保证主题怪物进入难度窗口。
- 底层按 `BranchDef.loot` 放置金币、宝石与随机物品，并在 8 格外放下 `boss`；
  标记 `town` 的底层强制生成一间商店，并按 `fountains` / `graves` 附加设施。
- 职业任务（`BranchDef.quest`）的怪物按 `role.c` 的 enemy1sym/enemy2sym 类别
  筛选；首层在入口楼梯附近放下领袖与护卫，领袖是和平生物，交谈一次解锁
  下行楼梯，底层在仇敌脚下放置本职业神器与一堆金币，带着神器回总部复命
  会标记任务完成，首次完成给 +1 幸运与 +5 阵营记录；目标栏按进度显示
  “见领袖、找神器、回总部复命”；中段搜索层额外放护卫与金币，目标层是一整间大厅。

### 推箱

推箱的关卡不由随机生成器生成，而是 `tools/extract-nh-sokoban.ts` 从原版
`dat/soko{1..4}-{1,2}.lua` 解析出的固定地图与摆放，写入 `src/data/sokoban.gen.ts`：
地图字符（`-`/`|`/`.`/`+`）、巨石、陷阱、门、楼梯、随机物品类别与顶层奖励。
`BranchDef.entryDepth = 4` 让玩家从底层进入（原版 `entry = -1`），层号 1 是顶层：

- 顶层奖励按 `percent(75)` 在次元袋与反射护身符之间二选一，另有两只巨型拟形怪；
- 整层照明并预先可见（原版 `lit` + `premapped`），不随机刷怪与物品；
- 巨石用 `makeBoulder` 生成，玩家朝它移动时能推就推、推不动原地不动且不耗时；
  推进坑洞陷阱时巨石与洞一起消失（原版 `dokick` 的填洞规则）；
- 层内传送、挖墙与破坏巨石的运气惩罚尚未实现，记在 `docs/COGNITION.md`。

## 尸体与内在抗性

- 击杀不是 `G_NOCORPSE` 的怪物时，一半概率在原地留下 `CORPSE` 物品；
  物品的 `corpse` 字段记录怪物原型 id，因此营养与赋予的抗性都从怪物数据推导。
- 吃尸体时营养取 `nutrition / 2`；尸体带形成回合，
  腐败程度按 `(当前回合 - 形成回合) / (10 + rn2(20))` 计算，大于 5 致病（`sick = 10 + rn2(10)`），
  3 到 5 之间有两成概率轻微致病；蜥蜴、地衣、酸块与天启骑士的尸体不腐。
- 有 `AD_DRST` 且没有毒素抗性的尸体会造成毒素伤害，
  有 `AD_ACID` 且没有酸蚀抗性的尸体会造成酸蚀伤害。
- 鸡蛇与美杜莎这类会石化的肉：没有石化抗性时直接石化死亡（`eat.c` 的 `cprefx`）。
- 内在抗性从怪物 `confers` 字段映射而来（火、冷、电、酸、毒、睡眠、分解、石化），
  尚未拥有的抗性按怪物等级掷骰获得：`rn2(15) < 等级`，与 `eat.c` 的 `should_givit` 一致。
- 内在抗性存在玩家的 `intrinsics` 列表里，与装备提供的抗性一起由 `playerResists` 合并，
  随存档保留；石化抗性会挡下 `AD_STON` 攻击。
- 浮游眼、夺心魔与夺心魔主的肉赋予心灵感应（`telepathy`）：渲染层会显示
  12 格内的怪物，即使隔着墙（`inventory.ts` 吃尸分支与 `entities.ts` 可见性）；
  ESP 护身符与心灵感应头盔在装备时同样提供该能力（`hasTelepathy()`）。
- 会传送的怪物（`M1_TPORT`）的肉按等级 / 10 的概率赋予传送症（`teleportitis`）：
  每回合有 1/85 概率随机传送（`upkeep()`）。
- 疾病（`Player.sick`）期间停止自然回复，每五回合掉 1 点生命，
  状态栏给出提醒；祈祷与完全治疗药水可治。
- 尸体不会自行消失，也不会被怪物捡走。

## 罐头

- `TIN` 与普通食物不同：吃之前需要背包里有开罐器，或手里持着武器；
  两者都没有时只给提示，罐头原样保留（`UseOutcome.keep`）。
- 内容在开启时按当前层数抽一只可生成的怪物并固定下来，营养取该怪物的
  `nutrition`；内容记录随存档保留。
- 未祝福的罐头有六分之一概率变质，造成伤害；变质不触发内在抗性。
- 同一物品堆里的罐头共享内容记录（内容在首次开启时确定）。

## 祝福与诅咒

物品的 BUC（祝福 / 未诅咒 / 诅咒）在使用时生效：

- 圣水（祝福的水）祝福整包物品；诅咒之水污染整包物品。
- 药水：祝福治疗提高生命上限，诅咒治疗效果减半；诅咒的能力药水反而降低幸运，
  诅咒的看见隐形失效；隐形时长随 BUC 变化；完全治疗药水不分 BUC 都解石化与疾病；
  加速药水让每次行动跳过怪物回合 30 次。
- 卷轴：祝福的强化卷轴 +2、诅咒 -1；祝福的鉴定卷轴一次鉴定全部；
  诅咒的移除诅咒与鉴定卷轴失效；新增祝福/诅咒生效的强化武器卷轴。
- 魔杖：祝福光束多一颗骰，诅咒少一颗（最低一颗）。
- 装备：被诅咒的装备无法取下与放下，解除诅咒（移除诅咒卷轴或圣水）后可取下；
  保护戒指与守护护身符按 `spec`（加上附魔）提供 AC；回复戒指加快自然回复，
  缓慢消化/饥饿戒指改变饱食度消耗，传送戒指带来随机传送；隐形戒指提供隐形，
  潜行戒指降低唤醒概率，搜索戒指每 10 回合显露身旁陷阱，毅力戒指抵挡属性吸取；
  变形戒指佩戴时偶尔把玩家变成随机怪物，力量戒指同时提高命中与伤害，
  命中/伤害戒指各加对应数值；挑衅戒指进入新层时唤醒全场怪物。
  携带幸运石按 BUC 提供幸运加值：诅咒 -1、普通 +1、祝福 +3。
- 武器：祝福武器对亡者与恶魔命中 +2、伤害 +1d4；银制武器对狼人、吸血鬼、
  恶魔、小恶魔与幽影伤害 +1d20（`weapon.c` 的 `mon_hates_blessings` 与 `mon_hates_silver`）。
- 充能卷轴：给充能最少的法杖补 2 点（祝福 3、诅咒 -1），
  用尽的魔法灯可以重新蓄力；没有目标时卷轴失效。

## 容器

箱子与袋子按 id 识别，容量按件数：箱子类 20、冰箱 8、袋类 8、空间袋 20。
背包菜单里非容器物品会多出「放进」，容器多出「打开」。

- 放进：默认选背包里第一个还有空间的容器；容器不能嵌套。
- 打开：把内容全部移回背包，放不下则落在脚下；诅咒的容器打不开；
  口袋袋打开会放出一只本层难度的怪物。
- 内容随物品一起递归序列化，嵌套内容写入存档。
- 地面容器（箱子、袋子等）踩在脚下时会多出「搜划」动作：把内容倒到地面；
  诅咒的地面容器同样搜划不开，口袋袋同样放出怪物。

## 视野与迷雾

- 玩家所在的照明房间整间可见，对应原版 `vision.c` 的行为。
- 其他位置使用八分区递归阴影投射，被墙体与关闭的门遮挡。
- `level.seen` 记录曾经看到过的瓦片，渲染层据此区分三种状态：
  未见不渲染，记忆中的瓦片压暗并偏冷，视野内正常照亮。

## 战斗与数值

命中与伤害直接移植自原版公式：

```
玩家攻击怪物：tmp = 1 + abon() + find_mac(mon) + uhitinc + 幸运修正 + 等级
              tmp > rnd(20) 时命中
怪物攻击玩家：tmp = AC_VALUE(玩家 AC) + 10 + 怪物等级
              tmp > rnd(20 + 攻击序号) 时命中
伤害减免：玩家 AC 为负时，按 rnd(-AC) 减免怪物伤害，最低为 1
```

经验值沿用 `experience()` 的组成方式，升级阈值沿用 `newuexp()`。

怪物攻击按 `AD_*` 分派：元素与魔法伤害走抗性判定（抗性完全免伤），
毒素附加力量流失，睡眠、麻痹、混乱、失明写入计时器，吸能抽法力、
吸级降等级，锈蚀与腐败降低盔甲附魔。偷窃与诱惑抢走背包里的一件物品后脱身，
妖精抢走一半金币，诅咒与去附魔作用于携带与穿戴的物品，取消清空魔法效果，
缠绕、吞下与抽腿造成伤害并定身。石化写入倒计时，归零时变成石头，
完全治疗药水可以解开；分解没有抗性时即死。变形、黏液与幻觉没有对应的
形态系统，以短暂混乱代替，边界记录在 `docs/COGNITION.md`。

近战命中后还会结算怪物的被动攻击（`AT_NONE`）：酸块、凝胶与孢子会反噬，
石化被手持的武器或手套隔开。玩家的抗性来自穿戴的装备：
戒指与护身符看 `power`，反射盾按物品 id，龙鳞甲按颜色；
反射把电击弹回攻击者，与 NetHack 的 `Reflecting` 判定一致。
怪物的抗性来自 `MR_*` 列表，法术效果另按 `mr` 百分比判定。
2-6 格外的怪物会用吐息、喷吐或魔法弹远程攻击（每回合有概率触发），
效果同样走抗性判定；玩家免疫该元素时怪物改为靠近。怪物从睡眠中醒来并看见玩家时，会唤醒 6 格内
尚在沉睡的同伴（宠物除外）。生命降到上限四分之一以下时，怪物有概率
转身逃跑（逃跑时不再主动攻击）。追击优先按直线靠近，被墙角挡住时
用一次最短路 BFS 决定下一步（关闭的门可以推开，其它生物视为阻挡）。

### 武器技能

每次近战命中都会给当前持握武器的技能累计使用次数；使用次数达到
`8 × (熟练度 + 1)` 时熟练度 +1（上限 7）。熟练度每两级提供 +1 命中，
每三级提供 +1 伤害。变形期间使用形态攻击，不计武器技能。
法术流派用同一张表，键为 `P_*_SPELL`：每次成功施法累计使用次数，
每级降低 3% 失败率，并给攻击与祛邪法术 +伤害。
熟练度与使用次数随存档保留。

### 武器附魔与职业神器

手中武器的附魔同时计入命中与伤害（强化卷轴祝福版 +2、普通 +1、诅咒 -1），
变形时不计算。每个职业在职业任务的最终层取得一件同名神器：以基础物品原型
加附魔表示，武器类附魔 +5，名字取自 `artifact.*`。非武器神器按 `artilist.h`
提供被动效果：探知之球与白金信用卡携带时给魔法抗性，圣洁法冠携带时给火焰抗性；
力量权杖、彼世之眼、埃塞俄比亚之眼装备时给魔法抗性，医神之杖在手时给吸取抗性
与加倍自然回复，黛安娜长弓持握时给反射；村正与命运之球携带时给 +2 幸运，
计入命中判定；命运之球与万能钥匙把物理伤害减半，命运之球、探知之球、
白金信用卡与埃塞俄比亚之眼把魔法伤害减半。可启动的神器（背包菜单的「启动」动作）
消耗一次充能：探知之球揭示全图，命运之球层级传送，黛安娜长弓造箭，
圣洁法冠回满法力，医神之杖治疗并除病，万能钥匙显露本层陷阱，
白金信用卡给背包里充能最少的物品补 2 点，彼世之眼同时揭示地形与陷阱；
非充能类首次启动获得 3 次机会。
仇敌在任务目标层守着神器，名字与地名取自 `role.c` 的 quest 字段，
任务线流程见「分支地牢」。

## 投掷与射击

远程攻击统一矄准视野内最近的敌对怪物，不需要手动选方向：

- 投掷：任何可投出的物品（武器、宝石、食物等）造成武器骰或 1d3 伤害，
  命中判定与近战相同，投出的物品落在目标格供回收；没有目标时不消耗物品。
- 射击：持握 `kind === 'BOW'` 的弓弩时，投射类武器获得 +2 命中加成。
- 可堆叠物品只消耗一件；被投出的单件物品会从背包中移除（若已装备则先卸下）。

## 物品与鉴定

- 类别按 `mkobj.c` 的 `mkobjprobs` 权重生成。
- 每局开始时洗牌未鉴定外观，与原版 `o_init.c` 的 `shuffle_all()` 一致；
  魔杖包含三个占位条目，因此有 3 个外观不会被使用，对应原版中 25 根魔杖与 28 种外观的关系。
- 未鉴定物品显示外观描述，鉴定后显示真实名称；祝福状态在鉴定前不可见。

## 商店

约四分之一的楼层（首层与底层除外）会把一间有门、没有楼梯的房间标为商店：

- 房间标记在生成阶段完成，判定用 `deriveSeed(gameSeed, 'shop-room', depth)`
  的独立随机流，不扰动其它楼层的陷阱与设施分布；商店房间不撒陷阱、
  不建设施，也不随机生成怪物。
- 货物与店主在进入楼层时放置（`ensureLevelPopulation`），同样使用派生随机流。
  房间内原有的地面物品收归商店，金币收进钱箱；新货按商店种类的库存表抽取
  （`game/items.ts` 的 `SHOP_TYPES`），标记为 `unpaid`。
- 商店有十种：杂货店最常见，另有武器店、护甲店、药水店、卷轴店、魔杖店、
  书店、珠宝店、食品店与五金店，各自的货品类别权重取自 NetHack 的 `shtypes[]`；
  进店时店主会按种类打招呼（`shop.*` 文案）。
- 商铺房间在铺货前只含店主与初始货物：骨头、分支宝藏、任务目标等特殊内容
  用 `floorSpot`/`farSpot` 挑选位置时排除商店房间，避免金币被收进钱箱。
- 店主是 `SHOPKEEPER`，站在门内侧，不睡觉。它属于和平生物（`M2_PEACEFUL`）：
  受挑衅前不行动，被攻击后转为敌对并可能追出店外。
- 拾取未付款商品时自动结账：售价为基础价加三分之一，魅力越高越便宜
  （魅力 10 时 `ceil(cost × 数量 × 4/3)`），金币不足时拒绝交易；把自有物品丢在店里，
  店主按半价收购，物品重新变成店产。店主不在场时无人收款，货物可以自由拿走。
- 商店每 200 回合在空地上补一件未付款的新货，货物同样来自该店的库存表。

## 存档

存档位于 localStorage，键为 `nethack3d.save.v1`，内容包含：

- 种子、当前深度、回合数、击杀数。
- 玩家属性、生命与法力、金币、饱食度、状态计时、背包与装备。
- 每个到访楼层的可变状态：迷雾、门、陷阱、地面物品、怪物；特殊楼层标识随几何一起重建。
- 物品的商店归属（`unpaid`）、怪物的敌对标记（`angry`）与驯服标记（`tame`）随实例存入存档。
- 玩家的计时状态（眩晕、石化倒计时、变形剩余回合）与阵营记录、祈祷冷却随玩家数据保存。

关卡几何不入档，由种子重建；这样存档体积小，且与生成算法的版本差异无关。
通关判定：带着尤恩多护身符回到第 1 层即胜利，拿到手本身不算；
途中尤恩多巫师会反复现身追击，近身时有概率抢走护身符并传送逃离，
击杀抢走护身符的巫师会使其掉回原地。

## 渲染

- 每层地牢构建一次网格：地板、墙体与液体各一个 InstancedMesh，
  地形设施按类型单独成组。
- 迷雾通过逐实例颜色与缩放实现：未见缩放为零，记忆按比例压暗，
  视野内使用基础色。
- 相机以固定仰角环绕玩家，位移带阻尼，支持拖拽与滚轮操作。
- 动画循环用 `renderer.setAnimationLoop`，像素比在窗口变化时重新应用，
  以适应在不同像素密度的显示器之间移动。
- 粒子池（上限 256）在命中时喷 10 粒、击杀时喷 26 粒，按速度与重力积分，
  寿命结束缩到 0，不产生运行时分配；火把飞灰每 0.35–0.6 秒在玩家身边升起 1 粒。
- 实时阴影：只有跟随玩家的月光投射阴影，阴影相机缩到 ±14 格以换取分辨率；
  地面与墙体实例接收阴影，人物、怪物与设施投射；低质量档改用基础阴影贴图。
  点光源做阴影要渲六面，开销太大，因此火把只照明不投影。
- 质量档位 `?quality=low` 关闭多重采样并把像素比固定为 1，高分屏上可把
  像素数降到四分之一。几何侧压力很小，真正的开销在填充率。

模型与音效素材来自 Kenney 的 Mini Dungeon、Mini Characters 与音频包（CC0），
由 `tools/sync-assets.ts` 同步到 `public/assets/kenney/` 并随仓库提交。
加载器把所有部件合并成一份几何体，共用一张调色板贴图；
素材缺失时返回空并让渲染层回退到程序化几何体。
门、楼梯、陷阱与人物使用模型，墙体、地面与兽类仍是程序化几何体：
它们走实例化加逐实例着色的迷雾管线，换成贴图模型需要重做颜色计算，留作后续。

渲染开销（无头浏览器，1258×566，像素比 1）：绘制约 27 次、三角面约 1.4 万个、
着色器程序 15 个、纹理 5 张。数值随在场怪物与物品数量变化，
由端到端报告中的 `metrics.render` 记录。

## 界面与引导

界面按「不需要先读说明书」设计，三层引导由弱到强：

1. **状态与目标**：状态格用标签加数值分行呈现，生命值带颜色分级，
   并常驻显示本局种子与当前层数，报问题时可以直接给出复现参数；
   角色创建页在选择阶段就显示种子，重掷时同步更新；
   底部常驻当前目标，玩家不必记住地牢有多深。
2. **情境操作**：只列出此刻可执行的动作用作按钮，按钮集合由局面推导
   （脚下有物品才出现拾取，相邻有怪物才出现攻击，楼梯已探索才出现前往楼梯）。
3. **鼠标移动**：点击地面自动走过去，路径在按钮栏上方预览；
   悬停任意格子给出名称与点击后果，背包里点击条目展开动作菜单。
4. **小地图**：右下角一块 80×21 像素的低分辨率概览，已探索地形按原色绘制，
   楼梯金色、分支楼梯蓝色、祭坛与坟墓有色、商店房间泛金、视野内怪物红色、
   玩家白色；自动移动时叠加淡蓝色路径。不拦截鼠标事件。

动作菜单只列出该物品真正可用的动作，并标出快捷键，避免让玩家先猜动词。
键盘路径保持原样：字母键直接执行默认动作，老玩家不必多一次点击。

问题反馈入口：HUD 的「转储」按钮把当前会话导出为纯文本——种子、层数、
角色状态、ASCII 地图与最近日志，末尾附 `serializeSession` 生成的存档 JSON。
复制或下载后即可附在反馈里；存档 JSON 可以写回 `localStorage` 恢复现场，
不必依赖操作回放。

寻路只经过已探索且可通行的格子，对角线移动要求两侧正交格都可通行。
这样自动移动不会把玩家带进未知区域，受伤或路径受阻时立即停下并交还控制权。
键盘操作会中断自动移动。

## 国际化

- 静态数据名称（怪物、物品、职业、种族、外观词）放在 `src/data/i18n.zh.ts`，
  以 NetHack 的稳定 ID 为键。
- 动态消息使用 `src/i18n` 的语言包键。
- 取值顺序为当前语言、英文、原始键名，缺失翻译不会导致空白或异常。

## 日志

`core/log.ts` 提供命名空间日志器，默认只输出 warn 与 error。
开关来自 URL 参数或本地存储，支持环形缓冲区与文本导出。
关键路径均埋点：关卡生成、视野、命中判定、物品生成、存档、渲染构建与语言切换。

## Agent 反馈循环

单人开发的游戏很难靠人工回归覆盖，因此把「可判定性」当作架构约束：
每个机制都必须能被程序判定。判定入口如下。

| 层次   | 入口                             | 判定方式                                       |
| ------ | -------------------------------- | ---------------------------------------------- |
| 单元   | `tools/selfcheck.test.ts`        | 公式、数据完整性、存档往返等断言，带覆盖率门槛 |
| 场景   | `tools/agent-scenarios.ts`       | 确定性游戏路径加逐步不变量校验                 |
| 模糊   | `tools/agent-loop.ts --fuzz`     | 随机种子与随机行动扩大覆盖                     |
| 地图   | `tools/agent-loop.ts --map-fuzz` | ASCII 地图审计门的形状与朝向等静态结构         |
| 浏览器 | `tools/agent-e2e.ts`             | 真实渲染、界面交互、控制台错误                 |

架构上的三条约定：

1. **不变量是契约**。`tools/agent-lib.ts` 的 `checkInvariants` 定义状态必须满足的条件；
   新增机制时同步补充不变量，否则循环发现不了该类回归。
2. **场景必须确定性**。只用 `newSession(seed)` 建立状态，失败可原样重放。
3. **报告面向机器**。失败项带复现命令与现场快照，产物写入 `tools/agent-artifacts/`。

快照回归（`tools/agent-golden.ts`）记录关卡地形与固定战斗轨迹的散列，
用于发现无意间的行为漂移；确认变更后用 `--update-golden` 更新基准。
机制细节与扩展方式见 `docs/AGENT-LOOP.md`。

## 法术

法术效果不硬编码，而是从法术书数据推导：`spellClass` 决定做什么
（攻击、治疗、祛邪、占卜、附魔、逃脱、物质），`level` 决定代价与强度。
46 种法术书因此共享同一套结算路径。

| 类别                | 效果                                   |
| ------------------- | -------------------------------------- |
| P_ATTACK_SPELL      | 伤害视野内最近的怪物，骰子随等级提高   |
| P_HEALING_SPELL     | 恢复生命                               |
| P_CLERIC_SPELL      | 优先重创不死生物，无目标时给予少量治疗 |
| P_DIVINATION_SPELL  | 揭开整层地图                           |
| P_ENCHANTMENT_SPELL | 使最近的怪物入睡                       |
| P_ESCAPE_SPELL      | 传送到本层随机地面                     |
| P_MATTER_SPELL      | 打开附近的门                           |
| P_NONE              | 无事发生                               |

代价等于法术等级（最低 1 点）。成功率由等级、智力与职业决定：
法师、牧师、医者与武僧有加成，高智力可以完全消除低阶法术的失败率。
失败时按原版规则损失一半法力；法力不足时直接拒绝且不消耗回合。

## 人物与音效

玩家与人形怪物用 Kenney Mini 系列的人物模型：每个模型自带 32 段骨骼动画，
常用的四段是 idle、walk、attack-melee-right 与 die。
`render/characters.ts` 用 `SkeletonUtils.clone` 复制蒙皮网格，
把材质统一成 Lambert 并按实例染色，因此同一模型能按怪物数据里的颜色与体型
产生足够差异。兽类（蚂蚁、蝙蝠、巨龙等）保留程序化外形，避免灰狼长着人形。

音效（`core/audio.ts`）在启动时解码全部音频；浏览器要求先有交互才能出声，
因此首次点击或按键时恢复音频上下文，静音开关记在 localStorage。
动作结果、战斗反馈与界面点击各自对应一个音效，脚步使用四个变体轮换并随机微调音高。

## 参考版本与数据同步

游戏数据来自外部仓库，因此数据的「版本」也是架构的一部分。

`tools/nethack-reference.json` 记录生成数据时的参考状态：提交号、分支、
关键文件散列与条目计数。判定分三层，任何一层变化都视为漂移：

1. 关键文件散列变化，内容级判定，未提交也能发现。
2. 参考文件中的条目数量变化。
3. 生成数据条数与记录不一致，说明提取脚本未重跑。

实现上优先使用文件系统：提交号与分支名解析 `.git/HEAD` 与 `packed-refs`，
内容比对用 sha256。这样高频调用不启动子进程，检查成本约 0.3 秒；
只有确认漂移、需要展示差异与提交列表时才调用 git。
漂移会出现在 Agent 报告的 `reference` 字段中，参考仓库不可用时静默降级。

上游更新后的同步流程见 `docs/NETHACK-SYNC.md`。

## 构建与开发服务器

Vite 配置保持最小集合（`vite.config.ts`），每项都有明确理由：

- `base: './'`：产物可放在任意子目录，也能直接用文件协议打开。
- `server.strictPort`：端口被占用时直接报错，避免自动化脚本连上来源不明的服务。
- `clearScreen: false`：保留终端输出，人工与 Agent 回看日志时不必重跑。
- `preview` 与开发服务器共用端口，便于替换验证生产产物。
- 客户端压缩器用 Vite 7 的默认值 oxc，与仓库的 oxlint、oxfmt 同源。
- `manualChunks` 把 three.js 单独分包，利用浏览器缓存。

实测结论，用于避免重复尝试：`build.target` 取 es2022、esnext 与 Vite 默认值，
产物完全一致；`server.warmup` 只能省约 60 毫秒，因此未启用；
three.js 已被有效摇树，产物中不含未使用的子系统。

开发服务器与生产产物的差异由端到端检查覆盖：默认检查开发服务器，
`--preview` 先构建再检查产物。发布前运行 `bun run verify:release`。
